# 05 — Plan: Snuggy Parking PWA

Reads: `01-questions.md` (AC ids), `03-design.md` (rev 5, approved), `04-outline.md` (approved). The id universe and coverage are as in the outline: 46 active ids, all claimed.

## Overview

Build Snuggy Parking, a household car-location PWA, from a pinned Laravel 13 / Inertia 3 / Vue 3 starter kit:
- Fortify is replaced by Google-only Socialite login.
- Households with invites, and parking spots with photo, map and directions.
- An installable, weak-signal-tolerant PWA.
- Everything runs in Sail Docker, with Pest tests for authorization.

## Desired End State

- **Docker.** `docker compose up -d` serves the app on `http://localhost` with pgsql and mailpit. `docker compose --profile tunnel up -d` exposes it over HTTPS.
- **Checks, all green inside `laravel.test`.**
  - `docker compose exec laravel.test composer test` runs pint `--test`, phpstan level 7 and Pest.
  - `npm run check` and `npm run types:check`.
- **Sign-in.** Google-only. Households, invites and parking work end to end, and the photo is private.
- **PWA.**
  - A production build is installable.
  - Previously seen pages and the last spot are viewable on a weak signal or offline.
  - User data on the device never crosses users.

## Behavior Contract

See `03-design.md` §Behavior Contract (intentional behavior change, greenfield). Nothing here changes it.

## Risks

- **Design R1–R13.** The ones most likely to fire during Implement:
  - R1 — Vite+ lint/types;
  - R2 — bind-mount speed;
  - R7 — SQLite vs pgsql;
  - R12 — `injectManifest` under Vite+.
- **Rule for every phase: re-verify against the live repo.** Every symbol, line number and option named here was taken from the reference scaffold or from documentation. Where the live tree differs, follow the live tree and report the deviation.

## Global conventions (every phase)

- **Commands.** Run all of them as `docker compose exec -u sail laravel.test <cmd>`. The one exception is P1's bootstrap steps, which name host commands explicitly.
  - **Chained commands** go through one shell so nothing after `&&` runs on the host: `docker compose exec -u sail laravel.test sh -c 'npm run build && npm run check && npm run types:check'` [PA-O3].
- **Authorization helper.** The kit's base `App\Http\Controllers\Controller` is empty. P2 adds `use Illuminate\Foundation\Auth\Access\AuthorizesRequests;` to it, so `$this->authorize()` works in every controller [PA-2].
- **Flash shape.** The kit's toast reads `flash.toast` (`lib/flashToast.ts`, `types/ui.ts`). Every flash is `Inertia::flash('toast', ['type' => 'success'|'info'|'warning'|'error', 'message' => '…'])`. Where this plan says "flash X", that is what it means [PA-S6].
- **Model style.** The kit uses PHP attributes such as `#[Hidden]` and `#[Fillable]`. New models follow the same style.
  - Every relation method declares Larastan generics, e.g. `/** @return BelongsTo<User, $this> */`.
  - Every model has `@property` docblocks for its columns, so phpstan level 7 passes [PA-6].
- **Before a phase is finished:**
  - `vendor/bin/pint --dirty`;
  - phpstan level 7 with zero errors;
  - Pest with zero failures. Run it as `php artisan test --compact` (there is no test cache to disable; Pest has none).
  - `npm run check` and `npm run types:check` for any frontend change.
- **Code style.** Match the kit's existing patterns:
  - Inertia 3 `<Form v-bind="X.form()">` with Wayfinder imports from `@/routes` and `@/actions`;
  - shadcn-vue primitives from `@/components/ui`;
  - PHP pint `laravel` preset, constructor property promotion, Form Requests for validation.
- **Tests.**
  - Pest feature tests under `tests/Feature/<Area>/`.
  - Authorization tests are **load-bearing**: each phase that adds a policy proves at least one denial test fails with the check removed (negative control), then restores it.
- **Wayfinder.** Route and action helpers are generated by the Vite plugin. After adding routes, run `php artisan wayfinder:generate` (inside the container) before `types:check`.
- **No speculative code.** Nothing beyond the design.

**`currentHousehold()` algorithm**, memoised in a private `?Household $resolvedCurrentHousehold` property:
1. If `current_household_id` is not null and `isMemberOf(current_household_id)`, return that household.
2. Else, if `ownedHouseholds()->orderBy('id')->first()` exists:
   - `forceFill(['current_household_id' => $h->id])->save()`;
   - return it.
3. Else return `app(CreatePersonalHousehold::class)($this)`.

**`app/Actions/CreatePersonalHousehold.php`**, signature `__invoke(User $user): Household`:
1. Start `DB::transaction`.
2. Run `User::whereKey($user->id)->lockForUpdate()->first()`.
3. If the user now owns a household, set current and return it.
4. Else:
   - create `Household(['name' => "{first word of name}'s household", 'owner_id' => $user->id])`;
   - `$user->households()->attach($h)`;
   - `$user->forceFill(['current_household_id' => $h->id])->save()`;
   - return it.

**`app/Http/Controllers/Auth/GoogleAuthController.php`:**
- `redirect(): RedirectResponse`. Returns `Socialite::driver('google')->with(['prompt' => 'select_account'])->redirect()`.
- `callback(Request $request): RedirectResponse`, in order:
  1. If `$request->has('error')`, `Inertia::flash('toast', ['type' => 'error', 'message' => 'Google sign-in was cancelled.'])` and redirect to `route('login')`.
  2. Call `$g = Socialite::driver('google')->user()` in try/catch for `InvalidStateException` and `\Throwable`. On failure, redirect to login with "Google sign-in failed, please try again."
  3. If `($g->user['email_verified'] ?? false) !== true` or `blank($g->getEmail())`, redirect to login with "Your Google account email isn't verified."
  4. Call `$user = $this->resolveUser($g)`. It returns `User|string`, where a string is a refusal message.
     - On `UniqueConstraintViolationException`, caught **outside** any transaction, call `resolveUser` once more.
  5. If the result is a string, redirect to login with it.
  6. `Auth::login($user)`, `$request->session()->regenerate()`, `redirect()->intended(route('home'))`.
- `private resolveUser(\Laravel\Socialite\Contracts\User $g): User|string`:
  1. `$email = Str::lower($g->getEmail())`.
  2. If `User::where('google_id', $g->getId())->first()` finds a user:
     - if `$email` belongs to another user, return the refusal "This email is linked to another Google account";
     - otherwise `forceFill(['email' => $email, 'avatar' => $g->getAvatar()])->save()` and return the user.
  3. Else, if `User::where('email', $email)->first()` finds a user:
     - if its `google_id` is not null, return the same refusal;
     - otherwise `forceFill(['google_id' => $g->getId(), 'avatar' => …])->save()` and return the user.
  4. Else, in `DB::transaction`:
     - `User::forceCreate(['name' => $g->getName() ?: $email, 'email' => $email, 'google_id' => $g->getId(), 'avatar' => $g->getAvatar()])`;
     - `app(CreatePersonalHousehold::class)($user)`;
     - return the user.
- `logout(Request $request): RedirectResponse`, in this order:
  1. `Auth::logout()`;
  2. `$request->session()->invalidate()`;
  3. `$request->session()->regenerateToken()`;
  4. redirect to `route('login')`.

  P6 adds `Inertia::clearHistory()` **after** step 3. `clearHistory` writes a session flag (ResponseFactory.php:189-192), and `invalidate()` would flush it [PA-8].

- **Routes, registered in this order.** All of them have `request.method === 'GET'`. Never-list paths are not matched, so they fall through to the network.
  1. **Navigations** (`request.mode === 'navigate' && !isNever(url)`):

  2. **Inertia GETs** (`request.headers.has('X-Inertia') && !request.headers.has('X-Inertia-Partial-Component') && !isNever(url)`): `NetworkFirst({ cacheName: 'inertia', networkTimeoutSeconds: 3, plugins: [okOnly, new ExpirationPlugin({ maxEntries: 30 })] })`.

Defaults: `busy_timeout` 5000, `journal_mode` WAL, `synchronous` NORMAL, `transaction_mode` IMMEDIATE (`lockForUpdate()` is a no-op on SQLite; IMMEDIATE serializes the household-locked sections). Back up with `sqlite3 db .backup`, not a file copy while running.
  - **PostgreSQL (e.g. Supabase free tier):** Session pooler, port 5432 (direct is IPv6-only on free; Transaction pooler 6543 breaks PDO prepares), `DB_USERNAME=postgres.<ref>`, `DB_SSLMODE=require`; free projects pause after ~7 idle days.
- **Known limitations:**
  - R8: the iOS installed-app sign-in result from AC21;
  - R13: the email lags until the next login;
  - no offline map (OSM policy);
  - no data deletion yet.

## Pre-Review Verification

**Runtime sequences traced.**

- [x] **Park:**
  1. Tap → `locate()` (client).
  2. `ParkSheet` writes the unsaved last spot and POSTs `/spots` (multipart, `household_id` from the Home props).
  3. FormRequest validates; the photo is stored before any lock.
  4. Transaction: lock the household → re-check membership → retrieve the active spot → insert.
  5. Redirect to `spots.show`. The Inertia XHR follows it; the SW does not cache redirected responses.
  6. Show renders and overwrites the last spot as `saved`.
  - Each step sees the right state. The client-side unsaved write happens **before** the request, so a failure at any later step leaves it in place.
- [x] **Login:**
  1. `/login` (guest) → `<a>` → `/auth/google/redirect` (throttle, `prompt`) → Google → `/auth/google/callback` (never SW-intercepted).
  2. `resolveUser` → `Auth::login` → regenerate → intended → Home.
  3. `syncDeviceUser` sets the pointer, or clears if the user changed.
  - The pointer is written **after** a fresh authenticated page. The login page's clear runs **before** any authenticated page, because a guest must render `auth/Login` first.
- [x] **Invite accept:**
  1. `/invites/{token}` (auth) → show → POST accept.
  2. Peek unlocked → lock household → lock invite → checks → attach → mark accepted → set current → redirect.

- [x] **Logout:**
  1. Form submit handler: clear caches and last-spot data (awaited) → native POST `/logout`.
  2. `Auth::logout` + invalidate + `clearHistory` → redirect `/login`.
  3. The login page clear runs again; idempotent.
